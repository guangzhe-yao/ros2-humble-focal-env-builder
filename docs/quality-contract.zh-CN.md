# 构建器质量契约

## 目标与非目标

交付对象是 Ubuntu 20.04 amd64 的 Humble 开发者：离线安装后可通过
ament/colcon 编译 C++、生成消息并使用 Python 类型支持。
环境包、通用依赖与业务包分开交付；runtime、SDK、Xenomai 由系统维护。
不承诺任意项目依赖全部离线可用，也不把开发环境测试当作机器人功能验收。

## 五阶段的具体落点

| 阶段 | 本仓库产物 | 完成标准 |
| --- | --- | --- |
| P0 约束 | AGENTS.md 与职责边界 | 修改范围、禁止事项、人工审核点明确 |
| P1 需求 | 本契约与本轮变更记录 | 每个修复对应可验证的失败场景 |
| P2 数据 | DEB control、包白名单、源码锁定记录、校验文件 | 名称/版本/架构一致，未知来源不伪装为已锁定 |
| P3 原型 | 命令行和文件布局 | 构建、候选发布、直接安装三个入口职责清楚，不制作无关 UI |
| P4 实现 | 小范围代码修改及回归测试 | 先复现问题，再修复并记录验证结果 |

## 输入输出契约

- `builder/package_installed_pico.sh` 读取干净 underlay，产生版本化候选包。
- 离线打包输入仅允许一个主 DEB 和一个同版本、同架构的 marker 归档。
- `runtime-deps.txt`、`dev-deps.txt` 是显式根依赖；DEB 的 Depends/Pre-Depends
  中所有备选项用于收集下载候选，安装时保留原始版本约束与 `A | B` 语义，由 apt 求解。
- 发布目录和版本名不能用来删除已有内容。已有同名候选必须换版本或由维护者明确清理，不能静默覆盖。
- `source-lock.repos` 只保存实际提供的构建来源记录；`third_party.repos` 是配置，不是来源证明。
- 安装继续使用包内 file 源；不改系统软件源、不启动业务节点、不卸载业务 DEB。

## 双重审核

自动防线：`bash tests/run_unit_tests.sh` 检查脚本语法、打包契约、依赖解析、
业务包隔离和重定位。无需 sudo，不联网，不操作实机。测试失败即停止，不自动安装缺少的测试工具。
发布内容变化时，再执行 [断网安装与开发验收](build-release-deploy.zh-CN.md)。

人工防线：维护者审核 P0 边界，以及目录清理、apt 安装/移除、源码版本和
依赖白名单变更。核对候选包的 SHA256、测试日志、未验证项后，才能更新 latest。
不以固定的 AI/人工百分比代替风险判断；AI 不能替人工签署审核。
